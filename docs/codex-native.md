# Explicit Codex JSONL source

Select one Codex session JSONL file you own or are authorized to read. Monitoring does not discover session directories, read credentials, run Codex or install hooks. Keep its path in private configuration:

```sh
python3 -m monitoring_ai serve --db /path/to/private/events.sqlite \
  --file /path/to/selected/codex-session.jsonl --format codex \
  --source-id owned-codex --project my-project
```

The local server polls the selected bounded file every two seconds. After its first scan, an in-memory cursor reads only newly completed lines. A trailing partial line waits for completion. The cursor commits after the corresponding ledger batch, and restart rescans the selected file with idempotent replay. File replacement or truncation replays from the beginning only if every previously accepted usage delta is still an exact ordered prefix; a partial rotated segment or changed prefix refuses and retains accepted history. This deliberately does not claim support for provider-driven segmented rotation. A parsed row is reduced before joining the retained row list: session identity from `session_meta`, model from `turn_context`, time and four cumulative counter fields from `event_msg`/`token_count`, plus timestamp, hashed turn ID and bounded timing values from `task_started`/`task_complete` markers. Prompt text, reasoning, tool arguments/results, working paths, account identifiers and unrelated rows are discarded. Raw bytes and each JSON object still exist transiently in the local reader while parsing. The source is capped at 32 MiB and 50,000 records. In-place edits to older lines of a growing file are not fully detected.

The adapter turns successive cumulative input, cached-input and output totals into disjoint event deltas. Cached input is subtracted from total input; reasoning output is already included in output. Identical cumulative totals add nothing, and decreasing totals or cached input greater than input refuse rather than fabricating a reset. A nonzero `cache_write_input_tokens` value refuses until its upstream accounting relationship is qualified. The separate `token_usage_record` rows are not imported or added to these cumulative deltas: on the selected source, their per-response sum did not equal the final cumulative buckets. Native session identity is hashed before ledger storage. No lifecycle or billed cost is inferred; dated model prices, if supplied separately, yield estimates only.

## Declared parent histories

A file declaring `session_meta.payload.forked_from_id` or `session_meta.payload.source.subagent.thread_spawn.parent_thread_id` is rejected before any of its records are imported. Non-null declarations, including malformed empty values, trigger the refusal. Only a boolean accounting constraint survives metadata projection. Parent identifiers and the nested source body are discarded.

Check the selection with `sources check` or `sources preview` before starting an owner. These commands and the running owner report: “Declared Codex parent history requires replay reconciliation.” Independent selected inputs continue. A rejected append or replacement retains the file's previously accepted history and cursor. The original file is never modified. For complete selected families without compaction, the separate [reconciled usage export](codex-replay-export.md) can prove and remove exact copied prefixes before creating a normalized input.

Newer metadata declarations are also refused: non-null `history_base`, top-level `parent_thread_id`, `subagent_history_start_ordinal` or `forked_from_ordinal_exclusive`, and any non-null `history_mode` other than `legacy`. Empty or malformed values refuse too; absent/null fields preserve the existing behavior. Native projection retains only a boolean constraint for these declarations. Source checks, previews and owner source-health panels report “Declared Codex history metadata requires separate accounting qualification.” The selected-family exporter and follower refuse these modes as well, even when counters happen to match a complete prefix.

This boundary follows inspection of OpenAI Codex's pinned [protocol definitions](https://github.com/openai/codex/blob/f2b94ef8b52196f127d162c6db71e390b9bb265c/codex-rs/protocol/src/protocol.rs) at `f2b94ef8b52196f127d162c6db71e390b9bb265c`. `HistoryPosition` identifies an immutable rollout prefix using an exclusive ordinal and byte offset; its `thread_id` field can identify a different rollout after revert, rather than the stable session thread. Monitoring does not interpret these offsets or equate those identities. This is source inspection plus synthetic refusal coverage, not qualification of an actual producer's paginated, reverted or inherited subagent history, nor evidence of a provider defect.

Forked histories can copy a parent's cumulative usage under a different session identity. A fictional two-file workflow previously accepted 358 tokens for 193 tokens of distinct work. The guard now accepts only the independent parent's 165 tokens and marks the child unavailable. The child's 28 new tokens remain unobserved. This prevents that demonstrated overcount without claiming complete accounting or automatic fork reconciliation.

Undeclared copied histories, per-response compaction accounting and real fork compatibility remain unqualified. No parent is discovered, matched by timing or read automatically. Existing ledger rows are not corrected or deleted. If a previous owner imported a declared fork, retain that ledger as historical evidence and use a new ledger with an independently verified source selection for corrected analysis. Do not remove the parent declaration to make the file pass.

Completed `CommandExecution`, `McpToolCall` and `FileChange` items in an explicitly selected Codex file now become metadata-only normalized tool events. The projection hashes item IDs and retains source timestamp, item type, bounded reported duration and safe MCP server/tool aliases; it discards commands, arguments, output, file changes and paths. A completed shell item with exit code zero is `ok`; failed status or nonzero exit is `error`. MCP and file-change completion alone does not establish success, so their outcome remains `unknown` unless explicitly failed. No token, cost, session closure, worker relation or current process state is inferred. A source that lacks these item types can still reconstruct usage; source coverage reports the adapter capability separately from actual observed tool count.
