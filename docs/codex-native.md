# Explicit Codex JSONL source

Select one Codex session JSONL file you own or are authorized to read. Monitoring does not discover session directories, read credentials, run Codex or install hooks. Keep its path in private configuration:

```sh
python3 -m monitoring_ai serve --db /path/to/private/events.sqlite \
  --file /path/to/selected/codex-session.jsonl --format codex \
  --source-id owned-codex --project my-project
```

The local server polls the selected bounded file every two seconds. After its first scan, an in-memory cursor reads only newly completed lines. A trailing partial line waits for completion. The cursor commits after the corresponding ledger batch, and restart rescans the selected file with idempotent replay. File replacement or truncation replays from the beginning only if every previously accepted usage delta is still an exact ordered prefix; a partial rotated segment or changed prefix refuses and retains accepted history. This deliberately does not claim support for provider-driven segmented rotation. A parsed row is reduced before joining the retained row list: session identity from `session_meta`, model from `turn_context`, time and four cumulative counter fields from `event_msg`/`token_count`, plus timestamp, hashed turn ID and bounded timing values from `task_started`/`task_complete` markers. Prompt text, reasoning, tool arguments/results, working paths, account identifiers and unrelated rows are discarded. Raw bytes and each JSON object still exist transiently in the local reader while parsing. The source is capped at 32 MiB and 50,000 records. In-place edits to older lines of a growing file are not fully detected.

The adapter turns successive cumulative input, cached-input and output totals into disjoint event deltas. Cached input is subtracted from total input; reasoning output is already included in output. Identical cumulative totals add nothing, and decreasing totals or cached input greater than input refuse rather than fabricating a reset. A nonzero `cache_write_input_tokens` value refuses until its upstream accounting relationship is qualified. The separate `token_usage_record` rows are not imported or added to these cumulative deltas: on the selected source, their per-response sum did not equal the final cumulative buckets. Native session identity is hashed before ledger storage. No lifecycle or billed cost is inferred; dated model prices, if supplied separately, yield estimates only.

Completed `CommandExecution`, `McpToolCall` and `FileChange` items in an explicitly selected Codex file now become metadata-only normalized tool events. The projection hashes item IDs and retains source timestamp, item type, bounded reported duration and safe MCP server/tool aliases; it discards commands, arguments, output, file changes and paths. A completed shell item with exit code zero is `ok`; failed status or nonzero exit is `error`. MCP and file-change completion alone does not establish success, so their outcome remains `unknown` unless explicitly failed. No token, cost, session closure, worker relation or current process state is inferred. A source that lacks these item types can still reconstruct usage; source coverage reports the adapter capability separately from actual observed tool count.
