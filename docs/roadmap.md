# Product roadmap

The goal is one useful view of local and explicitly connected AI activity, independently usable and consumable by Deep AI. Feature depth will grow through demonstrated user journeys.

| Stage | Scope | State |
| --- | --- | --- |
| Local foundation | Metadata ledger, hierarchy, chronology, tokens/costs, web/terminal views, filters, native file imports, read contract | Implemented alpha. Synthetic and fixture qualification. |
| Reliable daily use | Incremental cursors, source health details, correction protocol, retention controls, configurable evidence windows, deeper session drill-down and larger ledgers | Explicit multi-file configuration, independent read health, retained-history recovery, setup checks, disposable ingestion previews, capability-versus-observed coverage and scoped entity-history pages implemented. Incremental cursors, corrections and retention remain planned. |
| Connected sources | Reviewed adapters for more coding tools, supported OpenTelemetry ingestion and authorized cloud exports | Planned. No new credentials or hooks installed. |
| Quota and budgets | Independently sourced provider quota windows, reset times and budget notifications, with cost provenance preserved | Codex native allowance read and normalized quota imports implemented. Other collectors and budget notifications planned. No quota-to-dollar inference. |
| Rich analysis | Period reports, tool categories, timing, comparisons, exports and transparent forecasts | Source freshness, qualified linear scenarios, period comparisons, project/model/day reports, explicit tool categories and recorded-duration statistics implemented. Workflow-quality metrics and richer visual analysis need new supported evidence. |
| Shared appearance | Portable semantic palettes, system choice and validated local overrides | Shared package adopted with Monitoring controls and storage. Shared primary/contextual navigation geometry is adapted with independent layout preferences. Representative dashboard qualification accompanies each release. No automatic cross-application settings sync. |
| Deep integration | Reviewed same-origin bridge and unified monitoring view beside existing owner activity | Consumer adapter supplied. Deep source 95cbcdc mounts snapshot/reconnect views with synthetic checks. Detailed-report and managed-input additions await consumer adoption; live telemetry and UAT promotion remain unqualified. |

Public demos remain synthetic. A capability is implemented when its complete input-to-consumer journey works and its meaningful failure behavior is checked. Live personal-source qualification, user acceptance and production readiness remain separate evidence.

The [v1.0.0 acceptance requirements](release-readiness.md) govern release readiness separately from version numbers. Completed Claude CLI result capture adds a narrower authorized source with cumulative model-level accounting. It does not qualify interactive transcripts, general lifecycle discovery or cloud tracing.

Runtime-owned normalized emission and the parent-first Sessions view are qualified against one actual owned CLI review process. Source health responses now derive their aggregate status from the included inventory. General session discovery, continuous large-source retention and provider-internal lifecycle remain unqualified.

An explicitly selected CodeBurn v74 daily cache now supplies a separate replaceable daily view. It cannot establish session lifecycle, call chronology or a complete billing basis. Native per-call cache reconciliation and broader provider compatibility remain separate work.

An explicitly selected existing CodeBurn menubar status output can provide recent transcript-write observations with independent source-generation age. This optional compatibility adapter does not identify running processes or replace native provider collectors. A fresh source with represented sessions still needs actual qualification.

An owned Claude Code 2.1.308 JSONL source is qualified end to end for a fresh append: source message, metadata-only projection, normalized tokens, ledger replay, API revision and private dashboard. The explicit follower reads only complete appended lines after its first scan. A strictly later same-message token revision now has an auditable atomic replacement and new read revision; ambiguous versions refuse. Actual owned-source migration/replay kept two events and revision 2 with no observed correction; fictional correction/rotation/partial-line checks pass. This does not establish general directory discovery or lifecycle inference. Persistent large-history cursors, provider-driven rotation and wider real changed-usage qualification remain next source gaps.

A historical Codex `0.162.0-alpha.17.2` JSONL file now qualifies a second native source through projected parsing, 126 cumulative usage deltas, ledger replay, loopback API and private dashboard. Its input/cache-read/output sums matched the final source counters. Separate per-response records did not sum to those cumulative totals and remain excluded. The installed CLI inventory's `0.160.0` does not label this file. A fresh Codex append, incremental cursor, nonzero cache-write interpretation, broader source versions and lifecycle proof remain open.
