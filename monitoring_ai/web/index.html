Sources and connections

Explicitly select authorized inputs through the local CLI.

LOCAL CONFIGURATION

Monitoring does not discover files or create a manifest in the browser. Use the CLI to choose authorized inputs and keep the manifest private.

Set up an explicitly selected source
  1. Choose a normalized JSONL stream, a complete Claude Code or Codex session file, or an authorized completed Claude CLI result-summary JSON. The dashboard never scans for files.
  2. Create a private manifest with the CLI. For normalized input:
    python3 -m monitoring_ai sources create --output /path/to/private-sources.json --file /absolute/path/to/authorized.jsonl --id my-input --format normalized
    For Claude or Codex session files, choose --format claude or --format codex and add a project alias such as --project my-app.

    For a completed Claude CLI result summary, first capture a new metadata-only JSONL file from the explicit JSON result:

    python3 -m monitoring_ai sources capture-claude --file /path/to/authorized-result.json --captured-at TIME --output /path/to/claude-results.jsonl

    Then select that new file:

    python3 -m monitoring_ai sources create --output /path/to/private-sources.json --file /absolute/path/to/claude-results.jsonl --id my-claude-results --format claude-results --project my-app
    Capture uses the declared receipt time, not provider event time; it does not run models or scan directories and writes a new output rather than appending an existing file. Its totals can include subagent aggregate usage, not individual calls, turn times, or worker state. USD costs are client-side estimates, not billed spend or subscription balance; this route is not reconciled with Claude JSONL.
  3. Check the manifest and optionally preview against an existing ledger before starting:
    python3 -m monitoring_ai sources check --sources /path/to/private-sources.json
python3 -m monitoring_ai sources preview --sources /path/to/private-sources.json
python3 -m monitoring_ai serve --sources /path/to/private-sources.json --db /path/to/private-ledger.sqlite

Preview uses a disposable ledger copy. Add --db only to inspect an existing ledger. The default is an empty base. Files can change afterward. See README.md sections “Connect your data” and “Detailed reports” for command details. Manifests and input files stay on your machine.

Read an existing CodeBurn daily cache

Select an authorized v74 daily cache in the startup command:

python3 -m monitoring_ai serve --db /path/to/private-ledger.sqlite --codeburn-cache /path/to/selected/daily-cache.v74.json

Usage & costs shows these daily totals separately from events. Source-reported USD has an unknown billing basis. Monitoring reads the selected cache every five seconds without running CodeBurn or reading native transcripts. File age does not establish current worker activity.

Read an existing CodeBurn status file

Choose one existing CodeBurn 0.9.27 menubar status output:

python3 -m monitoring_ai serve --db /path/to/private-ledger.sqlite --codeburn-status /path/to/selected/menubar-status.json

Sessions shows the source-reported recent transcript writes with generation time and file age. This optional adapter reads only the selected output file. It does not run CodeBurn, read native transcripts or infer process liveness. Unknown and stale observations stay qualified.

Observe local AI processes

Start the service with --processes on macOS. The default sample interval is five seconds; --process-interval 2 through 60 adjusts it. The Sessions view then samples matching executable names every two seconds using OS process metadata. No command arguments or environment values are read. Process presence does not establish session or worker state.

python3 -m monitoring_ai serve --db /path/to/private-ledger.sqlite --processes
Only explicitly supplied sources are observed.
